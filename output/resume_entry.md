# 项目经历

**项目名称：电商人群圈选 Agent 效果评测与 Prompt 优化 | 个人项目　　　　2026.09 至 2026.10**

▸ 项目概述：模拟字节人群圈选 Agent 场景，用 LangGraph 编排意图路由、Prompt 生成 SQL、自愈重试、人群包输出的全链路，数据侧构建 3000 用户标签宽表落库 SQLite，支持自然语言圈选，依赖用 uv 管理并锁定版本。

▸ 项目过程：设计客观可复现的评测体系：以参考 SQL 为标准答案做人群集合比对，计算 Precision、Recall、F1，构造 32 条分层测试用例，覆盖简单、组合、时间窗口、歧义口径、矛盾需求、兜底六类场景，指标全自动计算，零人工打分。

▸ 项目成果：通过 3 版 Prompt 对照实验（基础版、角色加 Few Shot、规则约束版）量化 Prompt 工程收益：圈选通过率从 56.7% 提升至 96.7%，平均 F1 从 74.5% 提升至 99.8%；分层通过率定位歧义口径为词典注入无法解决的短板，用显式规则收敛至 100%。

▸ 完成 Bad case 自动归因，归纳为条件遗漏、口径偏差、时间口径、AND OR 混淆四类问题，沉淀优化后 Prompt 模板；兜底路由准确率 6/6，自愈机制实测触发并修复字段拼写错误。

## 面试口径备忘（自用，不写进简历）

1. 判定对错的方式：参考 SQL 即标准答案，跑出标准人群包与 Agent 结果做集合比对算 P/R/F1，F1 不低于 0.95 判定通过。
2. 为什么用路由不用 ReAct：圈选是模式化任务，路由前置更可控；ReAct 适合开放式多步任务。
3. 为什么不用 RAG 检索表结构：单表十几字段全文注入只有几千 token，上千张表的企业场景才需要向量检索。
4. 手写版与 LangGraph 版通过率一致（基础版 17/30，规则版 29/30），说明框架替换未影响业务效果。
